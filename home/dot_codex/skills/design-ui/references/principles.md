# 共性设计参考

这些原则跨项目适用，具体颜色、字号、密度、控件与平台快捷键由项目设计系统持有。
核心准则来自用户的本地工作流；外部来源只作注明范围的依据。

## 信息与视觉

- **一个区域围绕一个主要任务。** 主要内容和动作就近；导航、内容、编辑与反馈的层级稳定。
  低频选项逐步展开，但主要任务不依赖 hover、隐藏菜单或记忆才能发现。
- **先修结构，再补文字。** 同义标题、宣传标语、常驻操作教程和重复状态会稀释内容。
  删除前确认剩余布局、控件名称和状态仍足以完成任务；不要用占位文字代替必要的字段标签。
- **以对齐和节奏组织内容。** 优先排版、留白与稳定文字起点，避免用重复卡片、边框、阴影、
  徽章和工具栏制造层级。强调只给当前主要内容、动作或风险；不全屏同时争夺注意力。
- **密度服务任务。** 阅读、编辑、浏览和管理界面的密度不同；不要把营销官网的大留白机械套到
  工作台，也不要把工作台的控件密度套到阅读页。沿用项目已有的尺寸与 tokens。
- **内容变化仍成立。** 长标题、多语言、无结果、大量内容与窄布局保持可读、可达；
  明确谁滚动、谁收缩、谁截断，避免嵌套滚动和为一个样例写死尺寸。

## 交互与安全

动作名称、位置和结果保持一致。用户知道当前范围、正在发生的操作，以及失败后怎样继续。
编辑、取消、返回与重试遵守原有契约，错误不吞掉草稿；危险或不可逆操作保留必要保护。
仅呈现用户作决定所需的信息，不把内部模块、状态机或调试术语塞进页面。

键盘与焦点路径和鼠标任务一致。图标按钮有可访问名称，输入有关联标签，选择、禁用、加载和
失败状态可被识别。工具提示可补充信息，不能成为主要动作或重要错误的唯一解释。

## 同时判断 UX、DX、AX

| 视角           | 具体判断                                           | 应优先收敛的实现                               |
| -------------- | -------------------------------------------------- | ---------------------------------------------- |
| UX：用户体验   | 用户能否发现动作，理解范围和结果，完成或退出任务？ | 清晰布局、语义动作、必要反馈                   |
| DX：开发者体验 | 行为、样式、状态与生命周期能否找到唯一 owner？     | 现有组件与单一状态源，少转发、少特例           |
| AX：智能体体验 | 智能体能否识别对象、执行真实动作并确认结果？       | 稳定 role/name、资源身份、显式状态和可观察结果 |

三者不需要三套实现。比如一个有稳定名称、真实 disabled 状态和统一执行入口的按钮，
同时减少用户困惑、接线重复和自动化定位猜测。没有具体收益的抽象、设置项或 agent 专用层应省去。
无需给每次修改做三项打分；在方案选择与验收中能说明收益及没有破坏的关键行为即可。

## 用证据判断“干净”

- 同一页面反复解释“这里可以做什么”：检查主要动作、内容分组和名称，而不是继续补提示。
- 一排同等强调的按钮：确定主要任务与动作频率，再选择主次层级，不只统一改颜色。
- 重构后更短但多了一份 draft 或转发层：维护成本没有收敛，应回到真实状态 owner。
- 示例截图很整齐，真实长标题却挤掉动作：以真实内容与运行结果修正，不新增常量相等测试。

## 参考来源与采用范围

- [Nielsen 的十项可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/)：
  采用状态可见、用户控制、一致性、识别优于记忆、极简呈现和可恢复错误的原则。
- [W3C WAI：控件标签](https://www.w3.org/WAI/tutorials/forms/labels/)：
  采用明确关联的控件名称；视觉上省去重复标签时仍须保留可访问语义。

更新参考时核对原文，只吸收能解释实际取舍的内容，不复制整套设计指南或全局固定视觉参数。
