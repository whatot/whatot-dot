# 简洁的产品界面

目标简单、架构简单、设计简单、实现简单。以 Linear 官网或苹果备忘录的干净、克制作为方向，
具体布局与交互服从当前产品任务和平台。每个设计决定同时改善 UX、DX 与 AX，并保护现有行为。
AX 在这里指智能体体验；无障碍可访问性同样是需要保留的产品能力。

## 先确定任务与已有标准

先查项目 UI 规范、设计系统、真实组件入口及相邻页面，确认当前变更范围。
新建页面、调整信息架构或重构交互前，读取[共性设计参考](references/principles.md)；
小改也先核对其中与当前问题相关的判断，不加载无关技术手册。

用一句话明确用户在此处要完成的任务，确定主要内容、主要动作与必要状态。
沿用项目已确定的视觉语言与平台行为；缺少标准时，从现有产品和用户给定参照确定最小方向，
不临时引入第二套设计系统。Linear 官网与备忘录是简洁性的参照，不是可互换的页面模板。

## 必须遵守的约束

- **内容与任务优先。** 用布局、分组、对齐、层级和动作位置表达关系；页面只有依赖解释文字才能
  看懂时，先改布局与交互。砍掉标语、重复提示、次要标签和无助于当前任务的装饰。
- **简洁不损害理解。** 保留完成任务必需的控件名称、状态、错误原因、恢复入口与风险信息。
  不以删掉可访问名称、隐藏核心动作或取消数据保护来换取干净。
- **复用真实 owner。** 使用现有组件、主题 tokens 与交互惯例。状态、数据和生命周期有明确归属；
  不复制派生状态，不新增仅转发的 controller、adapter 或为一个页面设计通用框架。
- **UX、DX、AX 一起判断。** 用户能发现并完成任务，开发者能找到唯一实现与状态 owner，
  智能体能通过稳定语义、可访问名称和明确动作/结果理解并操作。用同一真实入口，不另建平行交互层。
- **保留支持的行为。** 布局精简不擅自删除功能或改变保存、取消、权限、导航与兼容契约。
  发现取舍时明确其影响；不要把“看起来更简单”当作删能力的授权。

## 实现与验收

先完成一个可运行的真实切片。复用框架已有的输入、焦点、菜单、列表与弹层能力；
只对真实缺口补最窄实现。组件边界按职责和状态生命周期划分，不按文件长度或命名对称拆层。

查看运行中的界面，修正实际字体层级、文字起点、间距、密度、对齐和动作显性。
按改动选择长内容、窄空间、主题、语言、空态、加载、失败、禁用等相关状态，
验证真实操作、键盘、焦点与必要的系统输入行为；不为每次小改复制完整状态矩阵。

保留来自当前实现的可追溯截图和相关交互证据；对照前后时固定尺寸、主题与输入数据。
编译、headless 测试、相同 token 和旧截图都不能证明当前视觉效果。原型与组件预览不替代真实页面接线。
无法运行时标记视觉/交互未验证，不能宣称验收完成。

需要新增或修改自动化测试时使用 `test-behavior`，不要为样式添加结构快照或常量自验。
交付时简短说明用户可见变化、删除的冗余、实际验收证据与未验证范围；不为每个决定建立额外台账。
