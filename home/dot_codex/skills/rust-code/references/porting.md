# 跨语言移植

先查真实调用者、原实现、独立输入样本及已有行为验证，确定要保留的公开行为。
包括错误分类、顺序、编码、空值、数值范围、持久格式和副作用；语言偶然结构不自动保留。

## 保留行为，简化结构

- 人工分配/释放改为有明确 owner 的资源，缺席/失败改为 `Option` / `Result`，
  out-parameter 改为返回值；保持调用者确实依赖的错误与资源释放语义。
- 原语言的 dict 顺序、宽整数、Unicode、浮点和空值规则可能与 Rust 不同。
  按支持输入与兼容承诺核对差异，不假定标准库同名操作必然等价。
- 不搬运只为原语言服务的继承、全局状态和手工缓冲层；也不顺便扩充 API、实现完整语言运行时，
  或为了行数比例改算法。
- 发现原行为疑似 bug 或支持范围含糊时，指出最小例子和影响。未经同意不静默修复，
  也不自行宣告边界输入“不重要”而改变既有契约。

## 验证与记录

按行为保证合并验证，不要求原测试与 Rust 测试一一对应，不无条件先移植全部测试。
复用真实公开入口与独立样本；确有差异风险时比较两端实际结果。
新增验证仍按 `test-behavior` 判断盲区、层级与工件，不能以“移植”为由复制冗余测试。

在项目已有变更说明或 OpenSpec 中记录必要的 API 对应、确认的差异、保留的特殊行为和执行证据。
只有确实需要长期查阅时才新增移植文档，不默认创建 `PORTING.md` 或测试逐条登记表。
