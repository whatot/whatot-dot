# API 与错误

按调用者和兼容承诺选择 API，避免把发布型库的演进策略施加到所有 workspace 内部代码。

## 所有权与类型

- 只读文本、序列和路径优先用 `&str`、`&[T]`、`&Path`；需要接管或保存数据时再接收拥有者。
  不先拿所有权再无故 clone，也不为消除分配承诺不必要的泛型。
- `Option` 表达缺席，`Result` 表达失败；身份、单位和非法组合确有混淆风险时才增加 newtype 或 enum。
  如果类型声称已验证，所有构造、反序列化和更新入口都要守住该不变量；不能只验证 `new()`。
- 普通记录、框架组件和 options 可以直接有公开字段；携带不变量、资源或状态转换的类型限制修改入口。
  不为所有字段生成同名 getter/setter。
- 按语义提供 `Clone`、`Copy`、`Default`、比较与转换 trait。唯一资源不为了方便而可复制，
  没有有效默认值就不造 `Default`；`Debug` 与 `Display` 不泄露密钥和敏感内容。
- `Eq`、`Ord`、`PartialOrd` 与 `Hash` 必须对同一身份/排序约定一致；手写一种后逐项核对相关实现。
  并非要求都手写，而是不能把派生与自定义实现组合成相互矛盾的契约。
- 缩窄数值转换用 `TryFrom` 或显式边界处理；保留有意的截断、饱和或回绕语义并使意图可见。
  输出需要稳定顺序时显式排序或使用合适集合，不依赖 `HashMap` 迭代顺序。

## 错误边界

调用者需要区分、恢复或映射的失败使用稳定的类型/分类；应用编排可以沿用现有上下文错误类型。
内部 crate 不因叫 library 就引入一套公开错误框架；也不把所有错误过早压成同一种字符串。
公开错误按需求实现 `Error`、`Display` 和 `source()`；只在真实线程/运行时边界要求 `Send + Sync`。

保留底层原因，并补足定位所需的操作、路径或身份；不在每层重复日志，不把 secret 放进错误。
输入违规、I/O 失败和可预期竞争不依赖 panic。意外不变量失败的处理沿用项目策略，
不能用 `catch_unwind` 把未知状态恢复成成功。

资源释放不能可靠完成的工作应有可等待、可返回错误的显式结束操作；`Drop` 保持有界、
避免 panic 或阻塞，并且不能承担必须成功的异步提交。失败后资源/数据由谁持有要明确。

## 兼容与文档

只有独立演进的下游、实际扩展计划或现有发布承诺需要时，才选择 `#[non_exhaustive]`、
sealed trait、隐藏第三方类型或 builder。内部穷举检查也有价值，不机械增加 wildcard 分支。
检查新增 trait bound、改字段可见性、错误类型及派生实现对已有调用者的影响。

文档说明调用者无法从签名得知的行为：失败与恢复、取消、副作用、顺序、单位、兼容和必要的安全条件。
不为简单内部转发生成复述名字的文档；公开库按其文档政策说明 `Errors`、`Panics` 和 `Safety`。

以上选择性吸收 BeautifulRust 的 API、trait 与错误原则；来源版本和未采用内容由
仓库 `docs/codex-skills.md` 统一记录。
