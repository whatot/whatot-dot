# 异步与生命周期

从资源 owner、任务结束条件和真实执行器检查并发；编译通过不等于生命周期正确。

## Task、取消与容量

- 每个后台 task 都有负责结束它的 owner：谁持有句柄，何时取消，何时等待完成，怎样观察失败。
  detach 只用于明确允许独立存活的工作；不让窗口、请求或服务结束后留下无主任务。
- 检查 future 在 `select!`、超时、断连和 owner 销毁时被 drop 的位置。局部 future 消失不代表
  已发出的远端写入或后台 task 被撤销；区分未执行、已完成和结果未知，沿用业务恢复与幂等契约。
- channel、队列和并发 task 有容量或背压归属。达到上限时谁等待、拒绝、丢弃或合并须符合业务，
  不用无界队列掩盖生产速度与消费能力不匹配。
- CPU 重活和阻塞 I/O 使用项目已有的执行池/阻塞入口；注意阻塞任务的取消限制与关闭等待。
  不把固定频率的 `yield_now` 当作阻塞调用或长计算的通用修复。

## 共享状态

锁只覆盖必要的状态操作；检查 guard 是否跨 `.await`、回调、外部 I/O 或复杂计算，
以及锁顺序、重入和关闭竞态。需要跨 await 的同步协议应明确选择相应原语并说明状态所有权，
不能仅把同步锁换成异步锁就认为问题已解决。

不要只为线程安全外观把单线程 GUI 状态换成 `Arc<Mutex<_>>`，也不要给所有 future 加 `Send`。
遵循框架的 UI 线程、本地 executor、弱引用和事件订阅生命周期；跨线程任务才承担实际需要的约束。
`Rc`、`RefCell` 和框架 entity 是工具，判断其借用和存活范围，不能仅凭类型名报错。

## Unsafe 与 FFI

先查项目是否允许 unsafe；禁止的项目不靠新增封装绕过。确需 unsafe 时把边界压到最小，
为每项操作证明指针有效性、别名、对齐、初始化、线程和生命周期条件；`SAFETY` 注释是证明的载体，
不能以一句“调用者保证”代替 safe API 自己必须建立的前提。

FFI 明确分配/释放配对、回调存活时间、线程与 ABI 约定；禁止向不允许 unwind 的边界传播 panic。
不通过 `transmute`、延长 lifetime 或无依据的 `unsafe impl Send/Sync` 压过编译器。
不要为当前任务引入自制锁、pinning 或执行器。

验证生命周期时按 `test-behavior` 选择真实行为盲区；不因为使用了 async 就复制一套取消测试矩阵。
