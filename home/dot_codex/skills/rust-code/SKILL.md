# 简洁可靠的 Rust

保留支持的行为，用最少的状态、抽象和公开面完成当前任务。实现与审查使用同一组判断，
不把某种 Rust 写法、代码行数或 lint 数量当作质量目标。

## 先读项目约束

查项目 `AGENTS.md`、Rust 规范、相关调用者、Cargo manifest 和工具入口，确认 edition、MSRV、
目标平台、feature 组合、框架及已有 lint。区分应用内部 API、共同演进的 workspace crate 和
独立发布的库；有 `lib.rs` 或跨 crate 调用不自动意味着需要公开库的全部兼容设计。

使用项目约定的格式化、Clippy、构建和测试命令，包括 `mise` 等 wrapper 与 Nextest。
不换成固定的 `cargo test`，不假定 `--all-features` 是有效配置，不擅自扩大检查矩阵。
发现规则冲突时指出具体条款和影响，保留更严格的项目约束，不静默覆盖。

## 实现时的核心判断

- **状态有唯一 owner。** 按真实共享和生命周期选择借用、所有权、`Rc` 或 `Arc`。
  不为绕过借用检查堆叠 clone、锁和内部可变性；也不为消灭一次合理 clone 引入复杂生命周期。
- **类型保护真实不变量。** 对会混淆的身份、单位和互斥状态使用类型；普通数据保持直接。
  bool 表达自然开关时可以保留，含糊的模式选择再换 enum 或命名操作；不批量增加 wrapper、builder、
  getter 或 trait。框架的普通数据组件、公开字段和本地执行器服从其契约。
- **错误留给能处理的边界。** 预期失败返回 `Result`，保留原因、必要上下文和可恢复数据；
  不吞错、不用默认值伪装成功，不把 `unwrap` 机械换成 `expect`。panic、锁中毒和恢复策略遵守项目
  不变量及运行边界，不套用“中毒必然退出”或“总能恢复”。
- **抽象必须有当前消费者。** 具体类型与固有方法足够时保持直接；trait 服务真实多态或边界。
  按职责、依赖和生命周期拆模块/crate，不按目录数量、文件长度或命名对称拆层。
- **守住契约。** 类型转换、排序、错误分类、持久格式和公开 API 的改动先查消费者。
  不为满足 lint 改变序列化值、数据语义、框架接线或兼容行为。

涉及 API、错误模型或手写标准 trait 时，读取 [API 与错误参考](references/api-and-errors.md)。
涉及 task、共享状态、取消、阻塞、unsafe 或 FFI 时，读取
[异步与生命周期参考](references/async-and-lifecycle.md)。
跨语言移植时另读[移植参考](references/porting.md)，迁移可观察行为，不逐行翻译原结构。

## Clippy 接入

新项目默认采用 `all + pedantic` 分组基线；存量项目先审阅诊断再收紧 CI，保留已有更严格规则。
不全开 `restriction` 或 `nursery`，不照搬 BeautifulRust 的整份配置。
新增、修改或评估 lint 时读取 [Clippy 基线与例外](references/clippy.md)，
将可执行配置留在项目 manifest 与 CI，不在全局注入 Cargo 配置。

## 审查与交付

审查 diff 及受影响的真实调用链，优先找错误结果、可达 panic、数据丢失、并发/资源生命周期、
trait 契约和兼容破坏，再考虑有实际成本的 API 与表达问题。
每项发现给出位置、触发条件、具体后果和最小修复方向；涉及 lint 或既有规范时给出依据。
合并同类问题，区分缺陷与有理由的取舍；风格偏好不能单独升级为缺陷，不凑数量或固定报告章节。
只有要求修改时才实施修复。

新增、修改或评审测试，以及判断回归测试是否必要时，使用 `test-behavior`；
产品 UI 同时使用 `design-ui` 与项目设计系统。这里不另设单测、Mock 或框架测试政策。

运行与改动相称的项目检查，报告实际执行、结果与未验证范围。
Clippy 通过不能证明业务、取消、持久化或视觉契约成立；需要对应的真实执行证据。
