# 行为判断与工件参考

本文件补充判断例子与取证方式。默认 E2E、禁止 Mock 和控制流、单测例外均为本地工作流选择；
外部资料只支撑下文注明的部分，不代表上游采用了整套政策。

## 行为契约与变更检测

变更检测测试仅记录当前实现“长什么样”，不能指出它保护的有效行为。
如果只改内部结构、实现顺序或视觉实现方式就失败，而用户结果与支持的契约不变，应删除或改写。

| 判断对象 | 无独有保证的检测                                  | 有效行为验证                                 |
| -------- | ------------------------------------------------- | -------------------------------------------- |
| 界面     | 组件读取了同一个高度常量、完整 DOM 快照、CSS 类名 | 长内容不溢出、动作可达、键盘与焦点符合交互   |
| 服务     | 私有 helper 调用次数或某个内部 DTO 的形状         | 真实请求被正确准入，结果能从公开入口读回     |
| 格式     | 用同一实现自编自解的普通往返                      | 独立存量样本仍可读取，承诺的外部格式保持兼容 |
| 错误     | 多种违规输入混在一起，只断言任意错误              | 隔离目标违规条件，验证真实拒绝原因与无副作用 |

固定输出不自动等于变更检测：若格式、文案或视觉本身是明确验收的产品契约，独立基准可以有价值。
禁止为保存当前实现而批量更新快照；纯样式变化通常以实际截图评审，不新增像素或 token 自验。

## 最小决策例子

- 修复某个入口后，已有 E2E 已能区分错误与正确行为：修正执行或接线，不再复制一个回归测试。
- 已有正常保存场景，却从未覆盖失败后草稿丢失：存在行为盲区，在真实保存链路补最小失败场景。
- 某 adapter 只转发已有能力：不复制下层规则矩阵；只有独有转换或真实接线缺失时补验证。
- 大量输入的复杂算法无法经产品入口触达必要边界：解释限制，直接验证真实纯函数；不用 Mock。

测试隔离是状态隔离，不是“每例都重启一切”的同义词。只有能够证明账户、命名空间、资源和
生命周期相互独立时才复用真实服务；复用导致顺序依赖、残留数据或相互影响就不合格。

## 工件最低要求

沿用项目 runner 和 CI 已有输出目录；没有输出机制时，只补满足当前场景的最小 reporter/附件接线。
不要为了执行此规范建立通用工件平台。

- **身份与重跑：** commit 或构建标识；工作区未提交时附可追溯差异；准确命令、用例选择器、
  必要运行时/平台/配置、输入 fixture 与随机种子。只记录允许公开的环境值，不导出整份环境。
- **判断依据：** 用例、预期结果、实际结果、退出状态与执行时间。报告应能定位失败阶段与证据文件，
  成功结果也需要真实输出，不能只有 runner 的汇总数字。
- **真实证据：** 按行为选择界面截图/trace、请求与响应、生成文件、持久化回读或相关进程日志。
  截图只能证明展示；保存成功需要真实读回，未知结果恢复需要对应执行证据。
- **失败与成本：** 由 runner 的生命周期机制保存失败/超时证据；无法产出时标明缺失。
  正常执行保留最小证据，按需保存较重 trace；脱敏并沿项目保留策略清理。

“可复现”要求能重建输入与执行条件；“可验证”要求第三方能从工件判断实际发生了什么。
它们不要求日志、时间戳或进程 ID 逐字节一致。

## 参考来源与采用范围

- [Playwright Best Practices](https://playwright.dev/docs/best-practices)：采用面向用户行为、测试隔离、
  语义定位和避免内部结构耦合的原则；不把 Playwright 设为所有项目的指定 runner。
- [Playwright Assertions](https://playwright.dev/docs/test-assertions)：采用有界、自动重试的状态断言，
  替代硬编码时间等待；不借重试重复执行业务写入。
