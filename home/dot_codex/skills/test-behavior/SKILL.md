# 测试真实行为

新增测试只补仍有效且尚未被可靠覆盖的行为，存量测试只保留独有保证。冗余测试和变更检测测试有害：它们增加维护成本，
并可能阻止不改变行为的重构。测试数量、覆盖率和“修过一个 bug”都不是新增测试的理由。

## 先判断是否存在盲区

查项目测试规范、真实公开入口、现有 E2E、runner 与 fixture；复用项目的执行入口。
若项目规则与本流程冲突，指出具体冲突及受影响范围，不静默改写项目规范或重构整个测试体系。
选择断言和验证工件前，读取[行为判断与工件参考](references/principles.md)。

新增测试前，按行为簇回答：

- 它保护哪个外部可观察的契约，能拦住哪一种现实错误实现？
- 现有场景为什么发现不了该错误？优先扩展已有场景，避免重复同一保证。
- 预期来自需求、独立样本或对外契约，还是从被测实现抄来的？

没有真正的行为盲区，就不要为错误修复新增回归测试。已有测试应发现但未发现问题时，
先检查执行入口、断言和 fixture，修正已有验证。需要新场景时，用最小复现说明错误实现会失败、
正确实现会通过；不要为此新增打分表或给每个测试写说明注释。

## 执行约束

- **默认只用 E2E。** 从产品真实公开入口穿过自有实现及真实依赖，验证最终可观察结果。
  UI 行为从真实界面进入；服务和 CLI 使用各自公开入口。直接调用内部 handler 不算 E2E。
- **单元测试只有两个例外。** 无法通过 E2E 覆盖的复杂纯计算逻辑，或无法通过 E2E 触达的极端异常分支。
  先说明无法覆盖的原因；运行慢、配置麻烦和想提高覆盖率都不是例外。不为同一保证叠加测试层。
- **禁止 Mock。** 唯一例外是无法控制的第三方外部服务，并标明替代边界及未验证范围。
  自有模块、数据库、队列、文件系统等用真实实现；不得换名为 fake、stub 或内存替身绕过限制。
- **测试完全隔离。** 数据、账户、会话、文件、端口和可变进程状态不跨用例泄漏；单独、乱序和并行运行
  都不依赖其他用例的准备或结果。清理完成后才结束测试；共享基础设施不得形成共享可变测试状态。
- **禁止硬编码等待。** 等待明确的事件、完成信号或有界条件；使用 runner 已有的自动等待和重试断言。
  超时只界定失败上限，不用固定 sleep、反复重跑或吞错掩盖竞态。
- **测试代码禁止控制流。** 用例、断言及其 fixture/helper 不写条件分支、循环或自制重试。
  不把这些逻辑藏进 helper、集合回调或异常捕获来绕过规则；按独立行为拆用例，等待与清理使用 runner 的原生能力。
- **不测试无业务保证的代码。** 不测试框架、第三方库、普通赋值、简单转发、自动派生或默认值本身。
  自有业务准入、真实接线、持久格式等有明确契约时，验证该契约。

## 最小场景与验收

只保留能触发错误的样本、步骤和断言。选择最小竞争、容量边界或真实中断点，不扩成字段、
页面和入口的笛卡尔积。重构后行为不变应继续通过；不要断言私有调用顺序、类名或实现结构。

每次 E2E 执行结束都产出可验证、可复现的工件，包括失败和超时：代码/构建身份、重跑命令、
必要环境与输入、预期和实际结果，以及来自真实执行的结果证据。沿用 runner 的报告与附件机制，
不新建测试平台；工件须脱敏且保留有界，不能只剩一句“通过”。

先运行对应场景，再完成项目要求的相关检查。新增、精简或删除测试后，简短说明独有保证、
实际执行和工件位置；未运行或未覆盖的范围如实记录。不把测试通过当作所有行为都未受影响的证明。
